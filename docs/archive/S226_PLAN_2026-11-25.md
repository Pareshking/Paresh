# S226 plan: NSE's four levels in place of TradingView's sector and industry (25 Nov 2026)

Owner, 24 Nov 2026: "remove trading views sector or Industry and use Screener 4 level for any filtering".
NSE's four levels (macro sector, sector, industry, basic industry) come from Screener.in's company page
(`scripts/nse_classification.py` -> `data/reference/nse_classification.csv`, S189 6 (a)); NSE's own index
lists win for the sector where they name one (`src/loaders/nse_classification.sector_map`).

The work splits in two. **(A)** readers that only show or filter: switched now, through one helper, each
level shown only when the file covers 90% of a system's stocks. **(B)** readers that move ranks, the
sector cap, backtests or the frozen record: measured, not switched; the owner decides (CLAUDE.md: not
taken alone).

## What was built (A)

- `src/loaders/nse_classification.py`: `levels_map`, `with_nse_levels`, `nse_levels_present`, `coverage`.
  `with_nse_levels(rank_df, system)` returns a **copy**: `Industry` as `with_nse_sectors` gives it (NSE's
  sector in the 750's spelling via `nse_industry`; today's value for a stock the file lacks), plus
  `NSE_Macro`, `NSE_Industry`, `NSE_Basic_Industry`, each only when it covers 90% of the rows. A stock the
  file lacks reads "Unclassified" at those levels, counted in `attrs["nse_unclassified"]`; TradingView's
  labels are never mixed into NSE's levels. `attrs["nse_sectors"]` says whether `Industry` is NSE's.
- `app.py` `_nse_display()`: the copy, passed only to the Screener and Sectors
  (`tests/test_s226_nse_levels.py::test_only_display_pages_get_the_nse_copy` pins that).
- Screener: the search offers NSE's macro sector, industry and basic industry; TradingView's two options
  are offered only when the copy carries no NSE level (the file short of 90%).
- Sectors: the picker offers NSE sector / macro sector / industry / basic industry; on Nano and Combined,
  once the sector passes the guard, NSE's sector indices are set beside NSE's sectors.
- Configuration: the data files table lists the NSE classification file.

Until the full sweep lands (the committed file is a 102-row sample) every page looks as it does today:
the guard keeps TradingView's options and Nano's TradingView grouping.

## (B): measured, not switched

`scripts/s226_measure.py` (tests in `tests/test_s226_nse_levels.py`) reports, today against NSE's sector:

1. **Labels**: each symbol whose cap group changes, and each group's count before and after (the record's
   map; with `--ranking`, the live plan's map too).
2. **The plan**: `plan_rebalance` on a ranking file both ways: sells, buys and weights that differ
   (`--ranking`, `--holdings`).
3. **A backtest**: `run_backtest` with the record's rules both ways: CAGR, total return, max drawdown,
   Sharpe, alpha, and the names held in each period that differ (`--prices`, `--months`, `--benchmark`).

It refuses below the 90% guard; `--force` runs a trial and marks it.

Trial on the sample file (25 Nov 2026, `--system nano --force`, labels only): NSE's sector is known for
197 of 411 stocks (48%, mostly from NSE's Nifty 1000 list); 63 of those change the record's cap group
(e.g. Metals & Mining 27 -> 15, Capital Goods 72 -> 86). The 750 and the Nifty 1000: 0 of their current
members change (NSE's lists already name them); only former members can move there, which the backtest
reading measures. Not a result: the sweep is not in.

**Finding, for the owner**: on Nano and Combined the live plan and the record already cap different
groupings. The plan caps by TradingView's 20 sectors (`app.py:1080`; "Producer Manufacturing", "Finance"),
the record's replay by `industry_for`'s NSE-voted industries: for 387 of the list's 411 stocks the two
labels differ. Whether the groups (not only the names) differ enough to change a book is what reading 2
answers once a ranking file is given; not measured here.
